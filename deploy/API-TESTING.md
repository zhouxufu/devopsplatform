# 接口文档与接口测试：第一版

接口文档、测试用例、执行测试是接口中心下的三个独立菜单，不嵌入应用构建页面。应用与环境沿用现有稳定应用 ID 和应用环境绑定，机器目标来自环境主机组，端口来自已有 Java / Docker 部署参数。文档中的 servers 不能覆盖测试目标。选中文档接口只创建请求草稿，不自动发送。

## 当前可用功能

- HTTP：GET / POST / PUT / PATCH / DELETE / HEAD / OPTIONS，路径参数、查询参数、请求头和 JSON / 文本正文。
- SSE：服务器端真实流式读取；展示 ID / event / 多行 data，接收过程中轮询显示。支持手工停止、事件数量上限及观察时间上限。不自动重连或使用 Last-Event-ID 重放。
- 认证：无需认证、引用已绑定变量中的 Bearer Token、先 POST 登录 JSON 再从响应 JSON Pointer 提取 Token。可配置 Token 请求头及前缀；认证服务与目标不同域时由管理员明确配置认证基础地址。
- 断言：HTTP 状态码、JSON Pointer 字段相等、正文包含、响应头相等、SSE 事件数量至少。无任意脚本执行。
- 测试用例：列表优先，按名称/编号/模块查询；编辑用例名称、模块、P0–P3 优先级、前置条件、测试数据，以及 1–10 个有序步骤（名称、操作、文字预期、HTTP/SSE 请求、自动断言）。旧单请求用例无损转换成一个步骤，读取不会改修订号。
- 执行测试：手动执行临时请求，或选择已保存用例执行。用例按服务端保存的指定修订读取全部步骤，客户端临时请求不能替换用例。每步成功后才执行下一步，失败/停止/未知时其余步骤标记“未执行”，无自动重试。
- 两类记录：**执行历史**只含手动执行；**测试用例执行记录**只含已保存用例执行。保存或编辑用例不产生执行记录；手动请求“保存为用例”不会将已有手动记录改类。旧记录按原 case_id 关联识别来源。
- 用例执行报告冻结用例版本、前置条件、数据说明、有序步骤、每步请求和响应/断言；修改或删除用例不改变历史报告。支持 JSON 报告导出。文档可生成用例草稿，保留快照关联。
- 请求生成 X-Request-ID 与 W3C traceparent；可带应用/环境上下文进入日志关键词查询或调用链查询。应用必须记录/透传标识且已接入采集，才会有对应数据；没有数据不表示请求失败。

## 第一轮操作体验改进（2026-10-22）

- 手动执行与用例步骤共用请求编辑器：路径参数、查询参数键值表格、请求头键值 / JSON 双模式、正文格式化、HTTP / SSE 选项和自动断言。JSON 模式无效时保留输入，不静默清空；请求头按大小写无关名称检查重复。未勾选请求头仅保留在当前编辑草稿，不发送；切换模式不丢弃未勾选行。步骤保存只保留实际请求，不将编辑器状态写进执行协议。
- 文档详情合并路径级公共参数与接口级参数，相同位置 / 名称由接口级定义覆盖，调试草稿使用同一解析逻辑。详情支持分组筛选、正文类型选择、已声明示例，以及默认值 / 枚举 / 约束；接口快照链接包含具体操作，打开后可直接查看该接口。此处没有实现完整的 OpenAPI 组合模型编辑器。
- 从文档生成请求时，优先使用已声明的 200，否则选第一个明确的 2xx 成功响应作为默认状态码断言；例如创建接口可默认 201、删除接口可默认 204。未声明明确 2xx 时不猜测默认状态码；多个合法响应仍由使用者调整断言。
- 路径参数值与查询参数表格中的合法 `{{var.NAME}}` / `{{step.NAME}}` 引用保留为模板，普通文字按 URL 组件编码。不会把变量提前编码成永不替换的普通文字，也不执行返回内容中的表达式。
- HTTP JSON 响应支持格式化、原文、可折叠字段表格、字段路径 / 值搜索及复制；基于实际字段生成具有原类型的断言。使用 `lossless-json` 保留大整数和数字精度；展示最多 500 个字段、16 层，原文仍保留在既有响应上限内。敏感或已遮蔽字段、截断响应不能通过点选生成断言 / 提取；提取仍遵循非空标量和 8 KiB 上限。
- 手动执行的字段断言加入当前请求草稿，不立即发送；用例报告中的字段操作打开对应步骤的用例草稿，可生成断言或响应提取定义，并定位新增行。只从同一用例、同一修订和未截断的 JSON 响应生成；旧版本报告不自动覆盖新用例，提取只保存来源路径与变量名。操作不修改历史报告，仍需使用者核对并保存。
- 报告汇总通过步骤、未执行步骤和断言结果，默认展开首个失败 / 未知 / 取消步骤，可一键定位。步骤响应不再在底部重复展示。新断言结果保存并展示脱敏后的期望值 / 实际值，细节展示有界；旧报告没有保存这些值时明确显示“旧记录未保存”，不事后伪造。
- 报告支持 `run` 链接按原记录读取；返回编辑清除该报告路由，保留当前请求草稿。同一工作区内更换接口 / 用例上下文时更新内容，未保存草稿仍需确认后才切换。

第一轮字段点选覆盖 HTTP JSON；第四轮进一步补齐 SSE 字段操作与 cURL 导入。团队协作与批量能力见第二轮，文档影响用例及编排测试节点见第三轮。

## 第二轮：团队用例与批量回归（2026-10-22）

- 测试用例仍以列表为入口，支持模块路径（例如 `订单/查询`，选父模块包含后代）、优先级、创建人、共享范围及名称/编号搜索。执行、编辑保留在行内，复制/删除收进 Arco Dropdown 的“更多”，避免操作列撑高。复制生成独立、仅自己可见的新草稿，不自动保存或执行。
- 旧用例默认“仅自己”。明确设置“团队可用”后，同一平台中可访问该应用的成员可查看、执行、复制；原作者及管理员可编辑/删除团队用例。管理员不因此读取或修改其他人的私人用例。共享的是请求模板与测试数据，应使用现有环境变量引用凭据。报告仍按执行人/应用隔离，不随用例共享。
- 测试集从测试用例页进入，先展示列表，新建/编辑时选择已有用例、调整顺序和共享范围，不重新录入请求、应用或连接。团队测试集仅能引用团队用例。定义不绑定环境，进入“执行测试”后才选已有应用环境、入口或机器。用例可展开预览前置条件和只读数据组。
- 数据驱动默认折叠，可选配置命名数据组、命名列及类型（文本、数字、布尔、null），使用官方 Table 编辑。数字以文本保存并按 JSON 数字执行，大整数不经过 JavaScript 浮点转换。空文本和 null 可用于参数校验场景。数据错误展开面板并定位字段；不存在的列在保存/执行前拒绝。
- 请求/断言可引用 `{{data.order_id}}`，与 `{{var.API_KEY}}`、`{{step.order_id}}` 分开。完整 JSON 值/JSON 相等断言保留数据类型；嵌入普通文本时空文本/null 展开为空串，URL 值按组件编码。每个用例数据组合有独立的步骤变量表。数据值不进行二次表达式求值，也不写回共享配置。
- 单次最多 20 个用例数据组合、100 步；单个用例仍最多 10 步、20 组数据、每组 20 列，单元格最多 8 KiB。整次测试另有 10 分钟上限，沿用全局 4 / 每用户 1 活动执行限制。按顺序执行，任一组合失败、取消或结果未知即跳过余下步骤与组合，不自动重试或恢复。
- 服务端在发送任何业务请求前核对测试集修订及所有用例修订、共享权限、文档身份、环境保护和目标指纹，并冻结实际计划。客户端草稿不能替换已保存步骤。共享撤回、用例删除或版本变化后，旧选择不可直接启动新执行。相同幂等键仍返回旧报告，不重新发送。受保护环境仍需管理员确认具体目标并填写原因。
- 批量报告先展示各用例/数据组状态，再按组合展开步骤，保留逐步断言、请求标识和日志关联。报告冻结每个用例修订、数据组名称、请求模板与文档证据；数据输入原值和运行时变量不作为报告变量表保存，响应按已知值脱敏。多数据组合报告暂不提供一键回写断言/提取，避免选错用例或步骤。
- 两类记录保持不变：手动请求进入执行历史；直接用例/测试集进入测试用例执行记录。历史新增服务端查询/分页，可按名称、环境、结果、用例、测试集及时间筛选；按用例筛选可命中包含它的测试集。旧报告以每批 50 条增量建立检索索引，不修改旧加密正文或伪造数据；返回报告保留原历史筛选。

跨用例变量关联已在第四轮补齐；CSV/Excel 导入数据、失败后继续执行开关、自动重跑、定时计划和团队共享执行报告仍未提供。文档变更影响分析和编排测试节点已在第三轮补齐。

## 文档生成与环境历史

接口文档支持按已有环境筛选，来源配置、自动生成开关和失败阻断策略按应用 + 环境保存。开发/测试用途的环境选择插件后默认自动生成；生产等其他环境默认关闭。配置路径可以不同，构建 Profiles、工具链、Runner 和凭据仍沿用本次环境与应用已有配置。

启用后，在构建弹窗选择本次构建环境；Webhook 可传 `build_environment`（自动发布已配置目标时沿用目标环境），无环境的旧 builds 入口会拒绝并提示新入口。定时触发若未配置可确定的目标环境，不推断分支、不启动未区分环境的文档构建。高级流水线会显示已配置的生成环境，运行详情有独立的“生成接口文档 · 插件 · 环境”阶段。生成后保存本次制品关联快照，自动与同环境上一份快照对比，提供“查看文档”和“变更历史”。各环境不互相覆盖，也不会拿开发文档冒充生产文档。旧记录没有可验证环境时保持“未区分环境”。

变更历史显示新增、删除和修改接口；“查看对比 → 查看字段”可查看字段原值/新值，包括本地共享 schema 引用所影响的接口。可以选择同环境更早快照重新对比。相同内容的新构建仍保留一份构建关联记录，并显示零接口变化。首次文档以空基线展示全部新增。

## 配置一次，环境内复用

执行测试 → 选择已有应用、环境 → **连接与认证**（管理员）。默认直接使用已绑定机器，不要求再录入主机、SSH 账号或日志配置。

如需域名/网关入口，可选填基础地址（包含统一 context path，不含查询参数与凭据）。配置按应用 ID + 环境保存，当前供此环境下的所有接口测试共用。只有配置入口/认证需要管理员；普通环境测试和个人用例可由成员执行。受保护环境仅管理员明确确认目标并填写原因后可执行。默认优先选择非受保护环境。

凭据优先使用应用已绑定变量组或该应用环境的加密变量，例如：

```json
{
  "username": "{{var.API_USERNAME}}",
  "password": "{{var.API_PASSWORD}}"
}
```

若登录响应为 `{"data":{"token":"..."}}`，提取路径填 `/data/token`，请求头 `Authorization`，前缀 `Bearer `（含末尾空格）。每个请求步骤独立获取 Token，登录失败或提取失败不会继续业务请求；不跨用户缓存 Token，不在业务 401 时自动重发请求。已有变量值不会回传浏览器。

目标地址、环境保护状态、配置修订及所记录制品变化后，旧目标指纹失效，需“刷新目标”重新确认。记录中的“制品”取该目标最近成功部署的记录，只是关联证据，不证明机器当前实际运行该制品，更不证明健康。环境入口可能经过负载均衡，因此不宣称知道它实际命中的机器。

## 步骤间变量传递

在用例步骤的 **响应提取** 页签中添加变量。例如第一步 POST `/orders` 返回 `{"data":{"id":"order-42"}}`，设置：

| 变量名 | 来源 | 字段 |
| --- | --- | --- |
| order_id | JSON 响应正文 | /data/id |

第二步请求路径填 `/orders/{{step.order_id}}`，JSON 字段相等断言的字段填 `/data/id`、期望值填 `{{step.order_id}}`。编辑器列出前序步骤的可复制引用。路径、查询参数、请求头、正文和断言均可引用；正文 `{"id":"{{step.order_id}}"}` 的整个值替换保留字符串/数字/布尔类型，避免大整数丢失精度。JSON 相等断言中的完整引用同样按原类型比较。

- 来源支持 JSON 正文、响应头（大小写无关名称）、SSE 最后一条收到的事件的 data JSON。JSON 使用 JSON Pointer，可取数组字段如 `/data/0/id`；SSE 在事件上限、观察时长或正常结束后取最后收到的事件，不自动寻找某个事件类型。
- 每步最多 10 个变量，值为非空字符串、数字或布尔值（0 和 false 有效），单值最多 8 KiB；不接受整个对象/数组/null。变量名以英文字母或下划线开头，最多 64 字符，整个用例内不能重名，仅后续步骤可引用。
- `{{step.order_id}}` 与现有环境变量 `{{var.API_KEY}}` 分开；不覆盖共享配置。认证配置仍独立生效，配置的认证头优先于步骤请求头。
- 当前步骤请求与全部自动断言通过，并且所有提取成功后才一起传给后续步骤。字段不存在、空值、类型不符、响应截断或提取失败时，该步骤失败，后续步骤不发送。失败/取消/未知结果不重试，不自动恢复变量。
- 私有变量仅保存在当前用例执行内存中。报告保留提取配置和成功/失败原因，响应及已知变量值脱敏；不保存实际变量表。历史请求显示未替换的请求模板，不宣称是包含实际参数的完整报文。进程重启后不恢复执行。
- 替换仅扫描模板一次，不执行返回内容里的变量表达式或脚本。URL 中的替换值按组件编码，并再次校验请求；提取出的换行等非法请求头会拒绝发送。

## 执行与存储契约

- 请求由交付后端发出，执行机必须能访问目标网络；当前不经 SSH 隧道或远程 Runner 转发。
- 仅允许已绑定机器端口或管理员保存的基础地址。不接受请求中的绝对 URL、跨域路径、路径越界、Host/传输头覆盖。拒绝回环、链路本地、组播、未指定地址及已知元数据地址；允许管理员绑定的正常内网地址。DNS 解析后直接拨号到核对过的 IP；不使用进程 HTTP 代理，不跟随重定向，不跳过 TLS 证书验证。
- 每个步骤超时/观察时长 1–120 秒，每用例最多 10 步、每步 100 个 SSE 事件；多组合边界见第二轮说明；用例保存接口 JSON 总体积最多 384 KiB；单事件 64 KiB，总响应 1 MiB，请求正文 256 KiB。超限会截断/中止并明确标识，不当作完整内容做 JSON 字段断言。
- 先保存执行记录再发送；同一 application/user/request_id + 同一内容返回原记录，换内容使用同一 ID 会拒绝。执行不自动重试。最多全局 4 个、每用户 1 个活动测试。
- 登录 Token 仅在当前执行内存中使用；响应与事件里的常见敏感字段及已知凭据值脱敏；原始登录响应不保存。配置、用例和执行记录采用现有密钥加密入库。审计只保存应用、环境、方法等摘要，不保存请求正文或 Token。脱敏不是任意业务隐私识别器，仍需合理限制业务测试数据。
- 私人用例和报告按用户/应用隔离，团队用例使用上述显式共享权限。接口测试没有新增账号角色，也不改变已有发布审批、SQL/Redis/Nacos 执行契约。停止只结束当前测试接收，不能回滚已到达接口的业务操作。
- 状态 queued/running/success/failed/canceled/unknown。通过表示本次请求或用例各步骤及其自动断言通过；文字预期、前置条件与测试数据说明不会自动执行/验证，也不自动注入参数。步骤变量只在同一次用例执行内传递，不跨执行保存。通过不表示已发布或健康。连接/写入结果未知或进程重启后标记 unknown，不恢复重发。用户需按请求标识核对业务状态。

## 后端 API

均在既有插件网关 `/api/plugins/api-center/api/api-testing/` 下，继承平台登录：

| 方法 / 路径 | 用途 |
| --- | --- |
| GET context?service=&environment= | 已绑定环境、目标指纹及变量名称 |
| GET/PUT profile?service=&environment= | 管理员读取/保存入口与认证，revision 防覆盖 |
| GET/POST cases?service= | 自己及团队可用的用例列表 / 新增 |
| PUT/DELETE cases/{id}?service= | 更新修订 / 从列表移除（历史报告保留） |
| GET/POST suites?service=、PUT/DELETE suites/{id}?service= | 测试集列表、新增、按修订更新、移除 |
| POST runs?service= | 明确发起手动/用例/测试集执行，request_id 为稳定幂等键；测试集另传 suite_id、suite_revision、case_revisions |
| GET runs?service=&source=manual或case&page=1&page_size=15 | 当前执行人记录，返回 items/total/page/page_size；支持 search/environment/status/case_id/suite_id/from/to（秒时间戳）；省略 page 保留旧最近 100 条数组契约 |
| GET runs/{id}?service= | 脱敏结果、断言和 SSE 增量 |
| POST runs/{id}/stop?service= | 仅停止当前用户的活动测试 |

## 验证和当前边界

### 文档变更关联用例

## 第四轮：请求导入、正文、断言、SSE 与用例关联（2026-10-22）

- cURL：手动执行和用例步骤共用导入弹窗，先解析/预览，再显式替换请求草稿；不发送请求。支持普通 POSIX 单/双引号、续行、URL、方法、请求头、JSON/文本、URL 编码表单、multipart 文件占位、Basic/固定 Cookie、GET 参数、SSE 与超时。原主机仅供核对，实际目标仍取应用环境，路径相对目标基础地址；基础地址已有路径前缀时请核对避免重复。传输控制请求头移除并说明；重定向不跟随。遇到不支持的参数或 shell 运算直接拒绝，不静默丢弃。文件 `@路径` 仅生成待选择占位，必须重新选择浏览器文件；没有文件内容不会当作空文件发送。不执行 shell，不读取平台服务器文件，不修改环境配置。原命令不写浏览器持久存储。
- 正文：原始（兼容旧数据）、JSON、文本、`application/x-www-form-urlencoded`、`multipart/form-data`、二进制文件。正文类型切换保留当前编辑器内各类型草稿，保存/执行仅取激活类型。表单允许同名字段和变量值；multipart boundary 由执行器生成。使用官方 Upload 选择文件，请求原始表单/文件合计最多 256 KiB，URL 编码后也受 256 KiB 限制，最多 30 个字段。文件随用例定义加密保存，执行报告仅保存文件名/类型及脱敏占位；运行文件不进行模板替换。文件读取中拒绝保存/发送。
- 增强断言：正文正则、JSON 字符串字段正则、JSON 数值闭区间（期望格式 `[最小值,最大值]`）、业务请求/完整 SSE 观察总耗时上限（毫秒，含前置认证）、JSON Schema（可指定 JSON Pointer 子对象）。JSON 数值比较保持大整数精度；正则使用 Go RE2。Schema 使用 [jsonschema/v5](https://pkg.go.dev/github.com/santhosh-tekuri/jsonschema/v5) 校验器，支持内联 Schema 和文档内引用，禁用外部资源加载；沿用断言 4 KiB、每步最多 30 条限制。响应截断不能通过完整 JSON/Schema/正则校验。结果仍保存脱敏期望/实际值。
- SSE：官方 Table 持续展示事件类型/ID/数据，可按类型和关键词筛选；查看某条事件的 JSON 字段，生成 SSE 断言/提取草稿。选择器支持第一条、最后一条匹配事件以及从实际事件生成的指定匹配序号（`index:0` 起），默认类型为空的事件按 `message` 匹配。缺失事件导致断言/提取失败，不回退到不相关事件。手动执行添加当前草稿；同一修订的单用例报告打开原步骤草稿供核对保存，仍不改写历史。继续保留停止/观察时长/事件数量边界，不自动重连或重放。
- 用例变量关联：在测试集的官方 Collapse/Table 内配置“目标用例 + 目标变量名 ← 前序来源用例 + 提取变量 + 可选来源数据组”，目标请求通过 `{{case.order_id}}` 使用。来源有多组数据时必须明确选组；不生成笛卡尔积或隐式取最后一组。每测试集最多 40 条关联。保存、运行和编排冻结时验证顺序、变量定义、必需输入；调整顺序后无效关联不能继续保存/执行。单独执行含未绑定用例变量的用例会在发送前拒绝。
- 用例变量只在本次执行内传递，来源用例所有步骤成功后才发布，数据组步骤变量仍互相隔离。失败/停止/未知则跳过后续；无跨报告取值、共享环境写回或二次求值。测试集修订冻结关联配置，报告/执行前预览可查看映射名称和来源，但不保存运行变量值。既有编排测试节点直接复用这些能力，无新进程或专用协议。

验证与本地部署以 `deploy/UI-INTERACTION-ACCEPTANCE.md` 最新条目为准；合成服务验证不代表真实业务联调已完成。

## MCP 认证与测试入口（2026-11-06）

复用现有 MCP JSON-RPC、Key 绑定用户、应用/环境授权和 `confirm_platform_action`，不增加独立 Skill 协议。

读取 `get_api_test_profile` 后，修改其 `profile`，携带原 `revision` 调用 `configure_api_testing`。默认 `base_url/auth` 继续给已有环境入口和机器目标使用；新增 `entries` 支持最多 10 个独立入口，例如：

```json
{
  "key": "gateway",
  "label": "测试网关",
  "kind": "gateway",
  "base_url": "https://gateway.example.com",
  "path_prefix": "/orders",
  "auth": {
    "mode": "login",
    "base_url": "https://identity.example.com",
    "path": "/login",
    "body_type": "form",
    "body": "username={{var.API_USER}}&password={{var.API_PASSWORD}}",
    "token_pointer": "/data/accessToken",
    "injection": "header",
    "header": "Authorization",
    "prefix": "Bearer ",
    "identity_pointer": "/data/account",
    "expires_in_seconds": 1800,
    "refresh_mode": "per_request"
  }
}
```

`kind` 为 `direct/gateway`。业务 Base URL 仅协议、主机和端口，前缀单独填写；登录 Base URL 与业务入口独立。JSON 登录使用 `body_type:json` 和 JSON 正文；表单替换后按 URL 编码，密码中的 `&`、`+`、`=` 不会变成新参数。Token 可注入请求头、查询参数或 Cookie；查询参数/Cookie 通过 `name` 指定键名。查询参数会增加目标 URL 中出现凭据的机会，返回报告仍遮蔽实际值。

账号、密码、密钥和已有 Token 引用应用环境已有的加密变量或变量组。MCP 不接收这些凭据明文，也不返回变量值；登录参数除 `grant_type/scope/audience` 等公共协议值外使用变量引用。变量配置沿用应用环境入口，不把凭据写入 OpenAPI。旧内联配置读取后会提示改成引用，不能把遮蔽文本当密码保存。登录参数不放在 URL 查询串，旧查询串在 MCP 和目标元数据中遮蔽，先调整为 JSON／表单参数再执行。自定义认证请求头引用变量，公共 Content-Type、Accept、User-Agent 可直接配置。

刷新当前仅支持 **每次执行重新登录**，Token 只在本次请求内存中使用；`expires_in_seconds` 是配置说明，不是校验过的服务端有效期，不做跨执行缓存或 refresh-token 交换。已有 Bearer 变量每次读取，不代替其签发方刷新。拒绝 `on_401` 等失败后重放策略，不能因鉴权失败重放 POST 等业务请求。

执行前先读目标 `key/fingerprint`；预览冻结配置、凭据的私有摘要、目标及用例修订，确认时再核对。配置或变量变化需重新预览。确认 ID 为执行幂等键；中断/超时/结果未知只查询原操作和执行记录，不自动重新登录或重发。手动验证/调试保留在手动历史，用例执行保留在用例历史，不改旧记录。

验证报告的 `authentication` 包含实际登录地址、注入位置及可选登录响应身份。仅在登录成功、Token 提取成功且配置身份字段确实返回有效标量时，`identity_verified` 才为 true；它表示该登录响应字段的证据，不表示业务接口实际权限已验证；身份值仍按凭据脱敏规则处理，不能用 Token 字段冒充身份字段。未配置身份字段明确返回未验证；不猜测 JWT 或用户身份。登录原始响应及提取 Token 不入报告；业务报告的 `result.url` 为脱敏后的实际请求地址。真实环境登录和业务测试仍须单独确认，开发回归使用合成服务。


## Agent 协作与顺序画布首批实现（2026-11-13）

- 测试用例编辑增加画布/步骤列表视图，共用请求、断言、响应提取和数据组；画布支持节点选择、拖动布局、平移、缩放、适应视图及增删。点击源节点“连接”，再点击目标节点“连接”，将目标接在源节点之后。重新连接先校验完整用例与变量顺序，失败保留原步骤。

- MCP 新增 `get_agent_capabilities`、`get_task_context`、`list_api_test_cases`、`get_api_test_case`、`validate_api_test_case`、`save_api_test_case`。测试资产工具要求明确应用和已绑定环境；用例本身仍归应用，不随测试入口环境重复存储。

- 资产读取/静态校验需 `apitests:read`，预览保存需 `apitests:write`，执行仍需 `apitests:execute`。确认时再次核对身份、范围、可见定义和修订，CAS 拒绝并发覆盖；重复确认不重复创建。权限、确认或网络结果未知仍使用原操作状态核对。

## 第二批：条件、并行与布局持久化（2026-11-13）

本节扩展上一节的顺序画布。旧用例继续使用原顺序引擎；带图定义的用例使用图调度器，共享同一HTTP/SSE请求、认证、断言与变量提取底座。

### 图定义与编辑

- `definition_version:2` 的用例增加 `graph:{entry,concurrency,edges}`；`steps`保存稳定节点定义，数组顺序用于展示，执行依赖由连线决定。`graph.entry`引用节点ID，`concurrency`为1–4；每条边包含`from/to`，条件边另带字符串`branch:"true"/"false"`。
- `steps[].kind`支持`http`（省略时默认）、`condition`、`parallel`、`join`。条件节点带`condition:{variable,operator,expected:{type,value}}`，其他控制节点不发送HTTP请求；其请求与输出提取在保存时清空/限制。
- 条件变量使用`step.NAME/data.NAME/case.NAME`，判断支持`equals/not_equals/greater/less/exists`；期望值类型为string/number/boolean/null。数值比较保留大整数精度。响应字段需先通过上游响应提取定义成变量。
- 图须有唯一入口、唯一终点，无环且全部节点连接。接口只能有一个后继，条件须有真/假两条路径，并行开始分出2–4条路径，多输入必须通过汇合节点连接。一个用例仍最多10个节点（含控制节点）。
- 画布工具栏可添加条件、并行开始和汇合节点；在源节点选择连接或真/假端口，再在目标选择“接到此处”。图模式新增节点由用户明确接线；连线条目可以移除，可调整流程入口及最大并发。未完成的图保留在编辑草稿中，保存/执行前严格校验。
- 普通顺序用例添加控制节点时升级图定义。旧修订与报告保持原样。Agent先校验得到规范化v2定义后仍可预览保存到原v1用例；旧客户端不能覆盖已保存的v2图。

### 调度与变量

- 调度器等待所有前驱结果，再判断该节点是否属于选中路径。条件未选中的路径记`skipped`和`skip_reason:branch_not_selected`，不发送请求；汇合等待实际执行路径，跳过路径只提供已完成信号。
- 并行请求各自复制私有输入。只有成功完成的节点才发布输出；汇合后可使用多个已完成分支的输出。禁止直接读取并行兄弟或仅在其他条件路径中定义的变量。
- 静态校验遍历所有可能条件组合，确认每个活动路径的数据依赖均有效；跨用例映射还要求来源变量在所有成功路径都可输出。条件或数据缺失不会被当成默认false。
- 任一路径失败后不调度后续节点，已发出的其他请求继续记录实际结果；用户停止会取消在途接收。未知结果优先保留待核对，不自动重发，也不把取消视为业务回滚。
- 每运行最多4条请求路径并行，平台仍最多4个活动测试运行、每用户1个。新图与旧用例可以在同一测试集中按原测试集顺序组合，仍受20组合/100节点/10分钟上限约束。
- 报告按原图修订及参数组展示节点结果、条件选择和跳过原因。多参数组的运行画布一次展示选中的一组。图执行的耗时汇总标为“累计请求耗时”（各HTTP步骤耗时之和）。

### 布局与MCP

- 新增`api_test_layouts`，按应用、用例、当前用户和工作区保存节点坐标、缩放、平移与独立布局修订；纳入SQLite/MySQL建表、迁移目录和应用身份重绑。只保存布局字段，不包含请求、变量、凭据或执行目标。
- 拖动结束、缩放和适应视图会串行保存布局；关闭重开或刷新页面后恢复。仅查看/选择节点不写布局。节点内容修订、审批、运行快照不受布局变化影响。
- 布局采用CAS。冲突保留本地布局并提示重新读取；不会自动用服务器修订覆盖本地。保存用例时过滤已移除节点坐标，新节点在用例保存成功后才可写入布局。
- HTTP：`GET/PUT cases/{id}/layout?service=&workspace=`；`POST cases/{id}/layout/validate`只校验。均沿用现有登录与用例可见性，`workspace`省略时为`standalone`。
- MCP新增`get_api_test_layout`（apitests:read）和`save_api_test_layout`（apitests:write）。传入`service/environment/case_id`及可选workspace；保存携带完整layout和原revision，沿用预览确认，不执行测试。
- Codex创建图继续使用`validate_api_test_case/save_api_test_case`，通过`get_agent_capabilities`发现定义版本、节点类型及并发上限，执行仍走原`execute_api_test`与`get_api_test_run`。

当前边界：无环图；并行只支持等待全部活动路径的汇合；不增加任意脚本、失败后自动重试、失败恢复分支、循环或跨用户共享布局。图和布局代码尚未发布到真实环境。
