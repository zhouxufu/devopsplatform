# 交付流程统一与执行节点（2026-10-16）

## 已实现边界

- 部署编排的动态范围模板可包含 `preparation`（范围确认、人工审批、按范围合并构建 / 核验合入）与原有 `nodes`（正式审批与执行）。复用现有两种执行引擎，不将 Git 构建或业务写入塞进保存接口。
- 环境策略增加 `workflow_template_id`、`hotfix_template_id`。只允许绑定部署编排中的动态范围模板；Hotfix 只用于生产用途环境。绑定在服务端校验，不能改用标准交付或其他模板绕过。未绑定的旧环境保留原行为。
- 代码节点 `application_scope=delivery` 从已选代码变更解析应用，按应用去重；仅 SQL / 配置的应用不参与，明确选择已有制品的应用不重新构建。空范围明确跳过。不再接受旧固定应用准备节点。
- 分支优先级：节点应用覆盖 > 环境应用默认值 > 节点通用策略。支持 `{version}` 和单工作项的 `{work_item}`，展开后必须是合法分支；生产仍要求明确基线和新的 release/ 或 hotfix/ 目标，禁止猜测分支。重复热修复须使用新的目标分支，尚未自动生成唯一交付分支名。
- 用户在同一交付准备页预览范围、确认人、分支策略，建立任务、确认范围。代码任务先冻结并展示源提交，再使用原有启动接口明确确认合并 / 构建；生产源范围确认不被绕过。子代码任务绑定父流程，未确认、已取消或内容变化时禁止独立启动。
- 完成准备后自动接回制品和正式预检；正式执行单保存 `preparation_run_id`，页内可查看确认历史。预检和提交均不自动发布。

### 团队交付的范围确认（2026-11-19）

准备阶段的人工范围节点支持 `assignee_source=delivery_initiator`，页面名称为“本次交付发起人（开发／测试）”。新添加的范围节点默认使用此来源；已有节点不自动迁移。

- 有应用／环境交付权限的成员可以选择团队已有就绪变更发起自己的交付。预览按可信登录身份确定确认人，创建时冻结；不根据请求中的 `approvers` 或原变更登记人分配。变更的原作者、工作项关联及内容不转移。
- 页面和 `confirm_delivery_scope` 复用同一指定人、修订／摘要、工作项范围及审计检查。已授权跟进任务可以确认分配给任务所有者的该类节点，但不会代签其他人员，也不会跨过正式审批或人工验证。跟进任务既有的工作项权限和变更选择边界保持不变。
- 仅用于非受保护且用途为 development/test 的环境。生产、受保护环境必须使用其他明确的确认人来源；正式审批仍不能自审。
- 多人各自发起交付不代表同一应用／环境可以并行发布。原分支、构建和发布互斥规则继续生效，也不允许接管他人的冻结任务或授权。

配置入口：部署编排 → 编辑环境所用流程 → 准备阶段 → 范围确认 → 确认人来源。若需要所有变更登记人会签，保留“本次变更提交人”。调整模板或环境绑定会使引用旧修订的在途任务停止推进，因此应先完成／正式取消旧任务再切换；不得直接改写旧执行单的确认人或补造签名。

### 开发／测试通过 MCP 确认本人范围（2026-11-16）

使用本人绑定、具有 `delivery:prepare` 权限且覆盖目标应用／环境的 Key：

1. `get_delivery_run` 查看当前准备单。
2. `confirm_delivery_scope({run_id,environment,comment,work_item_ids?})` 只生成预览，包含本人、环境、原修订／摘要／节点、交付范围和实际确认工作项。省略工作项时仅选本人分配范围中尚未确认的项。
3. 向用户展示该预览，取得对这次冻结范围的明确同意后，再用返回的 ID 调用 `confirm_platform_action`。之前的泛化“继续”不代替具体预览后的确认。
4. 保存本人、意见、时间与工作项回执，按原会签／或签规则更新状态；原操作可用 `get_platform_action` 查询。确认范围本身不启动下一节点，也不合并、构建或部署。

此入口仅支持非受保护开发／测试环境的当前范围确认节点。Key 所有人必须是指定且启用的确认人，管理员也不能替别人签；正式审批、独立人工验证、生产与受保护环境仍通过页面处理。范围、修订、绑定策略、人员或权限改变会使原预览失效；并发或丢失回执只查询原记录，不自动重放。
- 研发工作台不再维护流程配置。旧 `/flows` 页面、旧版准备入口、`/api/research/flows` 系列接口、版本内的旧准备关联字段移除；不迁移、不适配独立旧流程。组合准备使用 `/api/delivery/preparations`，内部复用确认和代码引擎，不另建用户配置体系。
- 新记录使用 JSON 文档、deploy_meta，以及 feature_branch_plans、delivery_observations、delivery_script_locks，兼容 SQLite / MySQL。没有物理删除用户、应用、资源、工作项、普通编排模板或执行数据。旧独立准备记录不再是有效证据，不能继续执行；存量数据库中的未引用原始记录不做自动清库。

## 使用路径

1. 部署编排 → 编排模板：配置准备阶段、正式审核和执行节点。
2. 环境流程绑定：选择默认流程；生产可另选 Hotfix 流程，制品来源和应用分支可以设置默认值。
3. 从工作项或版本发起交付，选择环境后带出绑定流程；生产可以选择 Hotfix，不要求业务版本。
4. 在本页完成准备，核对制品与步骤，正式预检和审批后显式开始执行。

## 本批新增能力

- 工作项 → 维护交付内容 → 代码与应用 → 开始开发：按仓库去重，预览默认远程基线或明确分支 / SHA，生成唯一开发分支名称。确认后以 create-only Git 更新创建分支，不覆盖已有分支；成功后回填当前编辑项，保存草稿完成关联。部分成功或响应不确定只能读取核对，不自动补推。它不替代生产候选分支准备，也不因为 Bug 状态同步而静默写仓库。
- `verify`：独立人工验证 / HTTP 验证，绑定制品摘要和交付快照。准备阶段须在构建之后；已有制品在执行阶段验证。人工验证有独立人员、或签 / 会签和必填证据说明；机器验证要求接口返回实际应用、环境、制品身份及 passed。失败停止，变更范围或制品变化不能复用旧证明。不会自动覆盖共享测试环境。
- 发布节点 `monitor`：在批次暂停时采样，检查预热、完整窗口、数据新鲜度、最低流量、错误率、P95 和连续达标次数；只允许指定单应用，并要求应用环境开启批间暂停。当前制品 / 发布单 / 批次身份必须匹配。无数据、接口异常、过期、身份错误、阈值超限均暂停，不自动回滚。SAE 使用原变更单当前 Pipeline ID，继续前再次核对，不新建变更单；宿主机发布使用已完成批次索引。
- `script`：交付脚本在已登记、同环境、有显式凭据的非 root SSH 主机执行；不在平台进程、本地构建 Runner 或 SAE 宿主机运行。脚本正文通过 stdin，参数逐个引用，清理继承环境，连接及执行均限时。按主机持久化互斥，输出限长并脱敏已知凭据。生产要求审批；目标、凭据和脚本内容随快照锁定。结果不确定时保留主机锁，人工核对只记录结果，不重跑。脚本由可信管理员维护，不是运行不可信代码的安全沙箱。
- 模板中的验证地址、指标地址及脚本由管理员维护；发起人不能在单次交付中替换或新增这些操作。审批页和执行快照可展开核对完整脚本、参数、主机、验证地址和监控阈值。

## HTTP 适配约定

HTTP 验证只发送 GET，参数为 service、environment、artifact_digest。接口必须实际检查所部署制品和业务结果，不可直接回显参数并固定 passed=true。示例响应：

```json
{"service":"orders","environment":"test","artifact_digest":"sha256:实际运行制品摘要","passed":true}
```

监控适配接口只发送 GET；参数增加 release_id、batch、window_start、window_seconds。响应必须来自能够按当前批次 / 修订过滤的指标源，不能使用新旧实例混合的全应用指标：

```json
{"service":"orders","environment":"test","artifact_digest":"sha256:实际摘要","release_id":123,"batch":"实际SAE Pipeline ID或hosts-1","window_start":1792100000,"window_end":1792100060,"requests":200,"error_rate":0.001,"p95_ms":120}
```

地址不接受内嵌账号、查询参数和片段；不跟随重定向，不访问回环、链路本地及已知云元数据地址。支持可达的内网 HTTP(S)，HTTPS 保持证书校验。当前不向检查接口注入认证头；需要鉴权时应由受控内网适配服务承接，不把密钥写入 URL。

## 仍需专项联调 / 后续工作

- 自动选择 Hotfix 的实际生产基线、唯一生产候选分支及热修复回合并待办；当前须明确基线并配置独立发布分支。
- 独立构建 / 制品复用节点的完整抽象、自动推荐制品、共享测试环境预约及自动测试部署；当前复用合并构建节点和显式制品来源选择。
- SAE ARMS / Prometheus 的具体指标适配服务尚未内置。监控门禁及自动继续已接入，但必须提供符合上述身份和窗口约定的受信任指标接口；未接入时继续使用人工观察。不能把本地模拟验收当成真实云监控联调完成。
- 脚本密钥引用、独立隔离 Runner、更多执行语言，以及进一步的插件进程拆分。当前参数为普通参数，不应填入密钥；脚本内也不应硬编码密钥。
- 多应用自由推进依赖面板与统一业务验收视图；不保证跨资源原子回退。
- 跨浏览器 / 跨设备的完整服务端交付草稿；本窗口草稿沿用 sessionStorage，服务端保留准备及执行记录。

## 验证方式

- `TestWorkflow*`：临时数据库验证绑定不可绕过、动态范围去重、已有制品与无代码跳过、缺失策略阻止、占位符、确认前代码启动禁止、范围 / 流程漂移、取消传播、独立变更提交人和版本证据关联。
- `workflowPreparation.test.js`：输入身份对比不受 Go / JavaScript 映射键顺序影响；范围、环境、流程、制品来源变化失效；令牌和临时结果不影响恢复。
- `serve-delivery-workflow-fixture.mjs`：本地内存模拟业务 API，浏览器验证环境绑定、页内确认、预检及提交后记录关联；不访问任何业务仓库、数据库、Nacos 或 SAE。
- 真实 Git 合并 / Runner 构建 / SAE 发布，以及 MySQL 实例专项联调不在本批浏览器验证范围内。
