# 应用构建与标准 Java 发布

目标是直接配置“用什么工具构建、发布到哪里、如何判断服务可用”，不需要复制 Jpom 的 Docker 命令或启停 DSL。

## 从禅道同步平台成员

1. 在资源中心 → 连接添加 **禅道 16.0**，填写实际安装根地址、专用同步账号与密码。同步账号需要组织/用户列表查看权限；只同步用户时无需填写产品 ID，Bug 自动同步周期保持 `0`。
2. 点击壳右上角管理员账号 → **成员管理 → 从禅道同步**，选择连接，点击“读取用户”。查看新增、更新、同名冲突等结果后，选择用户并确认同步。
3. 新用户固定为成员、默认停用。在成员管理中编辑，设置平台密码（至少 8 位）并启用后，才可登录。用户同步不是 SSO，不能读取或沿用禅道密码；平台未启用登录时仍是本地管理员模式。
4. 重复同步通过禅道安装地址与用户编号关联，仅更新姓名，保留平台用户名、角色、密码、启用状态。同名本地账号或其他来源账号不自动覆盖/关联；平台删除的同步账号不会被再次同步自动复活。
5. 禅道删除、停用或本次未返回的用户不会自动删除/停用平台账号；管理员需单独维护离职账号。审核人仍在环境中单独配置，不自动套用禅道权限。

用户同步由管理员手动发起，确认时重新读取禅道权威数据；分页或权限失败不保存部分用户。当前用户适配使用开源 16.0 的 `company/browse` JSON 会话接口，并不依赖新版 REST v1。身份映射随平台注册表迁移到 MySQL。

禅道地址仍填写安装根地址（例如 `http://host:8888/zentao/`），无需填写具体 API。平台获取会话时先尝试 `index.php?m=api&f=getSessionID&t=json`；遇到 HTML 登录页、路由跳转、404/405 或缺少 Session，自动探测 `api-getsessionid.json` 并沿用 PATHINFO 路由。Bug 与用户分页参数按 16.0 控制器顺序放在路径中，不会只替换登录 URL 而漏掉分页。账号认证失败不会换路由重试密码，以免触发账号锁定。兼容顶层 `user` 登录响应以及普通 `data` JSON/JSON 字符串响应；不把密码、Session 或上游响应正文写进错误提示。

登录 POST 携带同源 Referer，兼容 16.0 的 CSRF 校验，不需要关闭禅道防护，也不把密码或 Session 放进 URL。若代理丢弃 POST/Referer，平台会明确提示登录表单未转为认证结果，而不把 HTTP 200 当成登录成功。

只同步用户时，连接测试只验证登录认证，用户列表权限需到成员管理“读取用户”验证；同步 Bug 必须配置产品 ID。连接失败提示区分获取会话、登录认证、产品/Bug 读取与用户列表权限。旧版本本身不必因路由问题升级。

Bug 同步默认状态为**已关闭**，可选激活、已解决、未关闭、全部。在连接配置中保存默认状态 `bug_status`，定时同步沿用此值；手动同步可以单次覆盖，不改写连接默认。筛选不会删除或刷新本次范围之外已导入的记录。已关闭不等于尚未上线，历史上线范围仍需核对。

日期基线包含当天，匹配最后更新日期或关闭日期。分别按 `lastEditedDate_desc` 与 `closedDate_desc` 读取并合并去重；接口确认排序且翻页稳定时，遇到整页早于基线就停止，避免先扫描全部历史才筛日期。禅道 16.0 无原生“已关闭”浏览类型，关闭状态在日期范围读取后校验；激活/已解决/未关闭使用原生状态列表再校验。无排序元信息时不擅自提前结束，继续安全扫描。未设置日期会扫描历史，仍有每产品每排序流 10000 条保护；额外检查下一页避免恰好 10000 条误报。上限指历史扫描量，不是日期内的命中数，失败不保存部分结果。

接口依据：[禅道官方 16.0 用户列表源码](https://github.com/easysoft/zentaopms/blob/zentaopms_16.0/module/company/control.php)、[旧版 JSON API 机制](https://www.zentao.net/book/extension/api-intro-1241.html)。

## 需求、变更与版本的日常路径

- **需求与 BUG**：自定义需求直接新建；已有禅道 Bug 通过“同步禅道 BUG”导入，可按类型、状态和标题筛选。创建后进入需求详情，从“编辑交付内容”连续维护代码、SQL、Nacos 配置和其他操作，一次保存，自动关联当前需求。代码分支可以关联多个应用，新增内容可以同时关联其他需求/Bug。纳入版本后留在当前页面，按需点击“进入版本”。关闭状态来自需求平台，不代表已经上线。
- **变更列表**：既显示关联需求的变更，也显示独立变更，使用类型筛选区分。单项变更可直接纳入草稿版本，不必先建立需求。SQL 编辑器先选择应用，再选择该应用已声明的数据库资源；缺少资源时就地配置，关闭后保留原 SQL 和其他输入。
- **发布版本**：允许先创建空草稿，或先选需求再补实施内容。版本工作区集中显示需求范围、实施变更、待处理项和交付记录。需求关联变更与手工补入变更分别保存；取消需求时只移除其独有变更，共享与手工选中的变更保留。既有版本按“手工选择”兼容，不猜测历史需求范围。

需求后来新增了变更，草稿工作区会提示刷新关联范围；通过“刷新关联范围”或“编辑范围 → 保存”显式重新汇总。冻结前要求至少一项变更、所有变更就绪，每个需求有实施内容且没有漏掉新增关联变更。冻结后不可调整范围或退回其变更，避免已审批内容漂移。创建和保存版本本身不触发合并、构建、数据库执行或部署。

版本就绪后点击“发起交付”。只有一个适用编排时进入执行预览；有多个时明确选择，不自动取第一个；没有模板时引导创建，保存后继续当前版本的交付。执行页默认展示“执行与审核”，模板配置为次级操作。仍需明确选择每个应用的制品，平台不会把“最新制品”自动当作本次版本产物。执行单可刷新恢复，版本工作区可追溯其环境和结果。

低频配置不再常驻变更页面顶部：全局连接在公共资源中心管理，应用绑定在“应用详情 → 资源配置”或 SQL 编辑器中按需打开。公共中心与资源编辑弹窗不替换原工作页面。

需求/Bug 列表的说明只显示两行纯文本摘要（最多 180 个字符），不显示原始 HTML 标签。点击标题或“查看需求”进入详情，支持安全过滤后的段落、列表、强调、代码、表格和链接；较长说明默认折叠，可展开并在说明区域内滚动。纯文本保留换行，来源说明不被改写。脚本、事件、内嵌页面、样式及图片不渲染，避免执行外部代码或自动请求外部图片；附件/图片通过“外部记录”查看。相对链接按外部记录的地址解析，不跳到平台同名路径。

范围 API：`POST/PUT /api/release-versions[/{id}]` 使用 `work_item_ids` 与 `manual_change_ids` 保存选择来源，返回 `work_items`、`manual_change_ids` 与去重后的 `changes`。旧 `change_ids` 请求按手工选择兼容。版本与范围保存为同一事务，错误不会留下半更新的标题或选择项；SQLite 与 MySQL 均支持，迁移包含 `release_version_scope`。

批量交付接口：`GET/PUT /api/work-items/{id}/delivery-content`。GET 返回完整内容与 `digest`；PUT 使用该摘要提交 `changes` 和可选 `also_work_item_ids`（仅用于新增项）。全部校验与写入在同一事务完成；就绪项、他人内容不可编辑，遗漏项不删除，既有共享关联不移除。并发修改返回冲突而不是覆盖。弹窗关闭保留当前页面内存中的未保存草稿，再打开可继续；离开页面/刷新会提示，草稿不是持久存储，需点击保存。

当前 Nacos 支持保存结构化配置项（应用资源、Data ID、Group、格式、设置/删除项），但发布执行器仍未接通。Redis 与旧 `data-sync` 通用编排节点仍保持阻断；代码自动合并、版本级固定制品映射以及禅道上线状态回写也未接通。

## 可复用 MySQL 数据同步任务

入口：变更管控 → **数据同步任务**；也可从需求的“编辑交付内容”就地打开，返回后保留原输入。

1. 新建任务，选择应用、逻辑数据库资源、来源环境，填写来源/目标查询 SQL 和匹配键。连接依照应用环境资源绑定解析，不在任务中填写密码。任务保存后可反复使用。
2. 查询当前仅支持单表显式字段 `SELECT id,name FROM menu WHERE id > 0`，两个查询返回相同字段与顺序。禁止 `*`、别名、JOIN、函数、子查询、聚合、ORDER BY、LIMIT、变量与多语句；读取使用只读事务，最多 1000 行 / 2 MiB，UTF-8 文本单元格最多 64 KiB。匹配键必须完整对应目标主键或唯一索引，且结果无重复/NULL 键。
3. 选择本次目标环境，点击“对比数据（只读）”。展示新增/更新差异、原值与来源值；目标独有行保留，不生成删除。支持修改待同步值（包括 NULL），匹配键不可修改。
4. 勾选 1–50 行并“生成同步草稿”。服务器重新对比，任务/资源身份或来源/目标数据有变化则拒绝旧结果。草稿记录任务编号、修订、所选差异、目标环境和目标基线；从需求打开时自动关联该需求，不执行数据库写入。
5. 在变更列表或需求详情核对并标记就绪，纳入版本；部署编排添加 **SQL 节点**（可命名“菜单同步”）执行该草稿，再串服务发布和人工确认。上线依赖的是本次冻结同步计划，不能直接执行会不断变化的任务定义。
6. 生产等受保护环境必须审批，不能自审。预览/提交时再次校验目标数据与连接身份；执行时校验结构、绑定、内容摘要并锁定选中行，在一个 InnoDB 事务内更新，失败回滚，台账阻止重复执行。普通 SQL 的单表 DML 限制保留，仅同一同步快照的互不重叠唯一键操作允许批量执行。

复用任务到另一环境需要重新对比并生成该环境的草稿；已经生成的同步 SQL 不允许直接修改，不自动跟随任务后续修订变化。当前只实现新增和更新，不做自动删除、跨表关联、外键顺序推断或通用 Redis 同步；含反斜线转义等不被现有安全 SQL 方言支持的数据会在生成阶段报错，不会执行。SQL 草稿/差异快照包含实际业务值，不用于同步密钥，注意平台数据访问和备份权限。

API：`GET/POST /api/data-sync/tasks`、`PUT /api/data-sync/tasks/{id}`（带 `revision`）、`POST /api/data-sync/tasks/{id}/compare`（`environment`）、`POST /api/data-sync/tasks/{id}/freeze`（`environment`、对比 `digest`、`rows:[{key,after}]`，可选 `work_item_id/work_digest`）。任务元数据存于 `data_sync_tasks`，支持 SQLite/MySQL 及迁移；执行仍使用既有 `sql_execution_ledger`。

## 构建环境

入口：**接入/编辑应用 → 构建方式 → 构建环境**，也可在 **应用 → 构建** 或 **交付设置** 修改。

- **本机工具**：兼容旧应用，沿用 Runner 已安装的工具和 PATH/JAVA_HOME，不自动修改系统工具。
- **隔离容器**：按次启动临时构建容器，完成或超时后清理。可选 JDK 8/17/21 + Maven 3.9.9 或 Gradle 8.14.3，Node.js 20/22 + npm。
- **自定义镜像**：适合 Java + Node 组合、特殊编译工具、固定版本或内网镜像，例如已有的 `estate-gis-builder:java21-node22`。必须指定标签或 digest，镜像应包含 bash，并允许以 Runner 的 UID/GID 运行；不支持通过表单填写额外 Docker 参数或任意宿主机目录挂载。

`auto` 优先使用仓库里的 `mvnw` / `gradlew`，没有 Wrapper 时才使用所选环境内的 mvn / gradle。Wrapper 的版本不会被环境模板覆盖。平台对常见的 Gradle Wrapper/JDK 不兼容组合提前报错；完整兼容矩阵以 [Gradle 官方说明](https://docs.gradle.org/current/userguide/compatibility.html) 为准。

运行要求：

1. Docker 必须安装在**执行部署插件的 Runner 主机**上，平台运行账号能够访问 Docker 引擎。当前仍是本地 Runner，不是远程执行集群。
2. 首次构建可能下载镜像和 Wrapper/项目依赖；内网可先 `docker load` 导入镜像，使用自定义内网镜像并配置依赖仓库。不会自动修改宿主机 DNS 或使用 host 网络。
3. 镜像标签先解析为本地 image ID，再按该 ID 执行，实际 ID 和工具版本进入构建日志。已有本地镜像不自动更新；需要升级时由管理员更新镜像或更改配置。
4. 仅编译步骤进入容器；源码拉取和制品归档仍在宿主机。Docker 镜像构建继续使用本机 Docker，不挂载 Docker socket 到编译容器。
5. 挂载当前工作区、步骤脚本（只读）、输出目录和按应用/镜像隔离的缓存；Maven settings.xml 按配置只读挂载。HOME 为 `/lp-home`，Gradle 用户目录为 `/lp-home/.gradle`。不挂载整份宿主机 HOME、SSH 密钥或 Jpom secrets。
6. 构建变量组显式注入，敏感值不放 Docker 命令行；不要用变量组覆盖 HOME/PATH/JAVA_HOME/GRADLE_USER_HOME。Gradle 私服凭据仍通过 `GRADLE_REPOSITORY_URL/USERNAME/PASSWORD` 供项目读取。

此模式用于工具依赖隔离，**不是运行恶意代码的安全沙箱**。Docker 引擎访问权限接近主机管理员权限；不要开放给不可信用户，也没有自动资源配额或缓存淘汰功能。

## 一键部署

完成代码、构建和环境配置后，在应用标题区点击 **一键部署**，选择目标环境即可把一次操作串成：拉取代码 → 构建 → 登记不可变制品 → 创建发布单 → 自动发布。构建失败不会触发发布；普通环境会直接执行，受保护环境只创建待审批发布单，不会绕过审批。流水线详情会显示本次目标环境，并在构建完成后补充自动创建的发布单编号。

“开始构建”仍只生成制品，适合验证代码或后续手工选择发布版本；“一键部署”适合日常把当前分支直接交付到一个已经配置好的环境。开始前平台会检查主机组、审批人、发布原因和是否已有进行中的发布单，避免构建成功后才发现目标不可用。

## 标准 Java 发布

入口：**应用 → 环境 → 配置部署环境 → 标准 Java**。新建 Java 环境默认标准模式；旧环境继续使用原自定义命令，不自动切换。

1. 选择环境和该环境的主机组，填写独立部署目录（例如 `/home/work/zfb/ai/devops-service`）。
2. 选择运行 JDK 21，填写主机上的 JDK 目录 `/home/work/runtime/jdk-21`；留空使用主机 PATH 中的 java。不会自动安装 JDK。
3. JVM 参数每行一个，不加 shell 引号，例如：

   ```text
   -Xms256m
   -Xmx1024m
   -XX:+UseG1GC
   -Dfile.encoding=UTF-8
   -Duser.timezone=Asia/Shanghai
   ```

4. 应用参数每行一个，例如 `--server.port=8889`；**就绪检查端口**填 `8889`。端口字段仅用于检查，不改变程序监听配置。也可以填写应用真实存在的完整 HTTP 健康检查 URL，例如 `http://127.0.0.1:8889/actuator/health`；不要只填路径或盲填不存在的 actuator 地址。
5. 环境变量按环境配置并加密保存。例如开发环境设置 `SPRING_PROFILES_ACTIVE=dev`，测试设置 `SPRING_PROFILES_ACTIVE=test`；Nacos 注册 IP、网卡名及服务依赖地址分别按目标环境设置。模型 API Key 等敏感值只放环境变量，不写 JVM 参数或脚本。
6. **健康检查失败时**默认停止新版本并恢复旧版本。非保护环境也可选择“停止新版本、不恢复旧版本”或“保留新版本运行”以便排障；这两种情况发布仍标记失败并停止后续批次。受保护环境固定自动回滚。

发布过程：校验制品及应用 class 的 JDK 要求 → 上传新版本 → 检查主机 JDK → 优雅停止旧版本 → 切换 current → 启动 → 进程 + 端口/HTTP 就绪检查。嵌套依赖包的 JDK 要求仍需构建测试与启动检查确认。

每个版本拥有独立的 `app.jar`、`service.sh` 和权限受限的 `runtime.env`；回滚恢复旧制品及旧变量。进程 PID 必须对应当前版本的精确 JAR 路径，不能只凭 PID 或宽泛 pkill 杀进程。停机超时不会自动强杀；没有旧版本时首次发布失败不会显示为“已回滚”。

发布完成后可进入 **应用 → 环境 → 实例管理**，实时读取每台主机的进程、PID 和实际版本，并执行启动、停止、重启与就绪检查。实例操作与发布共用目录锁，发布进行中不能并发启停；受保护环境需要二次确认和操作原因，成功或失败都会写入审计日志。

目录示例：

```text
devops-service/
  current -> releases/deploy-123
  releases/deploy-123/{app.jar,service.sh,runtime.env}
  logs/application.log
  .devopsplatform.pid
  .devopsplatform-owner
```

注意：

- 标准模式只支持 Linux，使用 bash、coreutils；HTTP 检查需要 curl，检查地址从部署主机访问。端口检查使用 127.0.0.1，应用需监听该地址或通配地址。
- 不会自动停止/接管 Jpom 的进程。首次迁移先确认新配置，在发布窗口停止旧服务或选择独立端口，避免双平台争用。旧 Jpom 配置暂时保留作为人工回退方案。
- 单机替换存在短暂停机；这不是零停机部署。主机组可沿用平台分批发布机制。
- 当前标准模式使用受控的后台 Java 进程，不提供开机自启、崩溃自动重启；需要进程守护的场景继续使用自定义 systemd 命令。
- 历史版本和应用日志暂不自动清理，需要运维设置保留策略。`runtime.env` 是主机上权限受限的明文快照，应限制 SSH 用户和备份访问。
- 发布锁记录操作所有者和开始时间。升级前遗留的空锁会在下一次操作时自动恢复；带所有者的活动锁不会被其他发布删除，超过 30 分钟才会作为陈旧锁回收。日志会明确打印锁所有者和年龄，仍可据此排查异常中断。
