# 应用构建与标准 Java 发布

目标是直接配置“用什么工具构建、发布到哪里、如何判断服务可用”，不需要复制 Jpom 的 Docker 命令或启停 DSL。

## 从禅道同步平台成员

1. 在资源中心 → 连接添加 **禅道 16.0**，填写实际安装根地址、专用同步账号与密码。同步账号需要组织/用户列表查看权限；只同步用户时无需填写产品 ID，Bug 自动同步周期保持 `0`。
2. 点击壳右上角管理员账号 → **成员管理 → 从禅道同步**，选择连接，点击“读取用户”。查看新增、更新、同名冲突等结果后，选择用户并确认同步。
3. 新用户固定为成员、默认停用。在成员管理中编辑，设置平台密码（至少 8 位）并启用后，才可登录。用户同步不是 SSO，不能读取或沿用禅道密码；平台未启用登录时仍是本地管理员模式。
4. 重复同步通过禅道安装地址与用户编号关联，仅更新姓名，保留平台用户名、角色、密码、启用状态。同名本地账号或其他来源账号不自动覆盖/关联；平台删除的同步账号不会被再次同步自动复活。
5. 禅道删除、停用或本次未返回的用户不会自动删除/停用平台账号；管理员需单独维护离职账号。审核人仍在环境中单独配置，不自动套用禅道权限。

用户同步由管理员手动发起，确认时重新读取禅道权威数据；分页或权限失败不保存部分用户。当前用户适配使用开源 16.0 的 `company/browse` JSON 会话接口，并不依赖新版 REST v1。身份映射随平台注册表迁移到 MySQL。

禅道地址仍填写安装根地址（例如 `http://host:8888/zentao/`），无需填写具体 API。平台获取会话时先尝试 `index.php?m=api&f=getSessionID&t=json`；遇到 HTML 登录页、路由跳转、404/405 或缺少 Session，自动探测 `api-getsessionid.json` 并沿用 PATHINFO 路由。Bug 与用户分页参数按 16.0 控制器顺序放在路径中，不会只替换登录 URL 而漏掉分页。账号认证失败不会换路由重试密码，以免触发账号锁定。兼容顶层 `user` 登录响应以及普通 `data` JSON/JSON 字符串响应；不把密码、Session 或上游响应正文写进错误提示。

登录 POST 携带同源 Referer，兼容 16.0 的 CSRF 校验，不需要关闭禅道防护，也不把密码或 Session 放进 URL。若代理丢弃 POST/Referer，平台会明确提示登录表单未转为认证结果，而不把 HTTP 200 当成登录成功。

只同步用户时，连接测试只验证登录认证，用户列表权限需到成员管理“读取用户”验证；同步 Bug 必须配置产品 ID。连接失败提示区分获取会话、登录认证、产品/Bug 读取与用户列表权限。旧版本本身不必因路由问题升级。

Bug 同步默认状态为**已关闭**，可选激活、已解决、未关闭、全部。在连接配置中保存默认状态 `bug_status`，定时同步沿用此值；手动同步可以单次覆盖，不改写连接默认。筛选不会删除或刷新本次范围之外已导入的记录。已关闭不等于尚未上线，历史上线范围仍需核对。

日期基线包含当天，匹配最后更新日期或关闭日期。分别按 `lastEditedDate_desc` 与 `closedDate_desc` 读取并合并去重；接口确认排序且翻页稳定时，遇到整页早于基线就停止，避免先扫描全部历史才筛日期。禅道 16.0 无原生“已关闭”浏览类型，关闭状态在日期范围读取后校验；激活/已解决/未关闭使用原生状态列表再校验。无排序元信息时不擅自提前结束，继续安全扫描。未设置日期会扫描历史，仍有每产品每排序流 10000 条保护；额外检查下一页避免恰好 10000 条误报。上限指历史扫描量，不是日期内的命中数，失败不保存部分结果。

接口依据：[禅道官方 16.0 用户列表源码](https://github.com/easysoft/zentaopms/blob/zentaopms_16.0/module/company/control.php)、[旧版 JSON API 机制](https://www.zentao.net/book/extension/api-intro-1241.html)。

## 需求、变更与版本的日常路径

- **需求与 BUG**：自定义需求直接新建；已有禅道 Bug 通过“同步禅道 BUG”导入，可按类型、状态和标题筛选。创建后进入需求详情，从“编辑交付内容”连续维护代码、SQL、Nacos 配置和其他操作，一次保存，自动关联当前需求。代码分支可以关联多个应用，新增内容可以同时关联其他需求/Bug。纳入版本后留在当前页面，按需点击“进入版本”。关闭状态来自需求平台，不代表已经上线。
- **变更列表**：既显示关联需求的变更，也显示独立变更，使用类型筛选区分。单项变更可直接纳入草稿版本，不必先建立需求。SQL 编辑器先选择应用，再选择该应用已声明的数据库资源；缺少资源时就地配置，关闭后保留原 SQL 和其他输入。
- **发布版本**：允许先创建空草稿，或先选需求再补实施内容。版本工作区集中显示需求范围、实施变更、待处理项和交付记录。需求关联变更与手工补入变更分别保存；取消需求时只移除其独有变更，共享与手工选中的变更保留。既有版本按“手工选择”兼容，不猜测历史需求范围。

需求后来新增了变更，草稿工作区会提示刷新关联范围；通过“刷新关联范围”或“编辑范围 → 保存”显式重新汇总。冻结前要求至少一项变更、所有变更就绪，每个需求有实施内容且没有漏掉新增关联变更。冻结后不可调整范围或退回其变更，避免已审批内容漂移。创建和保存版本本身不触发合并、构建、数据库执行或部署。

版本就绪后点击“发起交付”，在连续页面中完成“选择范围 → 制品与步骤 → 预检提交”。有多个适用编排时明确选择，不自动取第一个；没有模板时在页面内创建，保存后继续原交付。执行页默认展示“执行与审核”，模板配置为次级操作。首次选择并关联版本制品，生成第一张执行单后锁定；测试到生产使用同一映射，不自动换成最新制品。执行单可刷新恢复，版本工作区可追溯其环境和结果。

低频配置不再常驻变更页面顶部：全局连接在公共资源中心管理，应用绑定在“应用详情 → 资源配置”或 SQL 编辑器中按需打开。公共中心与资源编辑弹窗不替换原工作页面。

需求/Bug 列表使用紧凑表格，不展开说明正文；支持人员、类型和状态筛选及服务端分页。点击标题或“查看”进入详情，支持安全过滤后的段落、列表、强调、代码、表格和链接；较长说明默认折叠，可展开并在说明区域内滚动。纯文本保留换行，来源说明不被改写。脚本、事件、内嵌页面及样式不渲染。图片保留文本标记与“查看图片”入口，只有点击后才在弹窗加载所选图片，不自动请求整组图片，也不代用平台凭据抓取附件；支持打开原图和多图切换，加载失败时可打开“外部记录”在来源平台登录后查看。外部图片地址仅允许无内嵌账号密码的 HTTP/HTTPS，拒绝脚本、data、file 等地址；平台上传图片通过受保护的附件接口读取。预览不发送来源 Referer。相对图片地址及链接按外部记录的地址解析，不跳到平台同名路径。

范围 API：`POST/PUT /api/release-versions[/{id}]` 使用 `work_item_ids` 与 `manual_change_ids` 保存选择来源，返回 `work_items`、`manual_change_ids` 与去重后的 `changes`。旧 `change_ids` 请求按手工选择兼容。版本与范围保存为同一事务，错误不会留下半更新的标题或选择项；SQLite 与 MySQL 均支持，迁移包含 `release_version_scope`。

批量交付接口：`GET/PUT /api/work-items/{id}/delivery-content`。GET 返回完整内容与 `digest`；PUT 使用该摘要提交 `changes` 和可选 `also_work_item_ids`（仅用于新增项）。全部校验与写入在同一事务完成；就绪项、他人内容不可编辑，遗漏项不删除，既有共享关联不移除。并发修改返回冲突而不是覆盖。弹窗关闭保留当前页面内存中的未保存草稿，再打开可继续；离开页面/刷新会提示，草稿不是持久存储，需点击保存。

Nacos 已接通结构化配置项的预览和受审核发布；Redis 已接通受限缓存维护命令，详见下文。版本级固定制品映射和显式启动的顺序推进已接通，代码覆盖仍需人工确认。旧 `data-sync` 通用编排节点仍保持阻断；代码自动合并和禅道上线状态回写未接通。数据同步任务生成的冻结 SQL 变更可通过 MySQL 节点执行，不使用旧通用节点。

## Nacos 配置预览、发布与恢复

1. 在资源中心创建 **Nacos 配置中心** 连接：本阶段支持 Nacos **2.4 / 2.5** 的兼容 v1 API，不支持 3.x 或阿里云 MSE 专用认证。填写完整服务根路径（如 `https://host:8848/nacos`）、命名空间 **ID**（public 留空）、专用账号密码；也可使用已有 Token，或可信内网无认证模式。Token 放在密码字段，加密保存；更换认证方式须重填凭据。连接测试只登录/读取指定测试 Data ID，不验证发布权限，不修改远端配置。
2. 在应用资源中声明 Nacos 别名，按环境绑定独立连接。命名空间配置在连接中，暂不支持资源绑定覆盖。
3. 在需求“交付内容”或“独立变更”中填 Data ID、Group、格式及配置项期望值。YAML / JSON 使用点路径设置或删除**标量**（`feature.enabled=true`）；值支持 JSON 标量和普通字符串，数字字符串写 `"123"`。不替换整个对象或数组。properties 只支持无转义、无续行的 `key=value/key:value`，值按原文保存。已有 YAML 锚点、别名、重复键、自定义类型或多文档会阻止自动改写。
4. “Nacos 差异预览”选择目标环境后只读获取配置；提交执行单时重新读取，并冻结全文基线、目标身份和逐项差异。可使用版本编排自动汇总配置变更，也可在没有部署节点的固定模式中显式选择独立配置变更，无需创建版本或选择应用制品。**仅修改已存在的配置**，不存在时不自动创建。
5. 受保护环境使用已有发布审核人和禁止自审规则；审批后执行前重新校验资源绑定、变更和当前全文摘要，发布使用 `casMd5` 并核对回读摘要，避免覆盖控制台并发修改。全文备份在元数据库中加密保存，不返回浏览器；逐项差异值会展示给审核者，勿将密钥作为普通配置项，部署时应启用身份认证并限制访问。
6. 发布成功的执行单可点击 **生成恢复草稿**。这不会立即操作远端：恢复草稿引用发布前完整文档，需标记就绪、重新预览和审核执行。若当前全文不再等于原发布结果，或环境/连接变化，会阻止恢复；恢复包括原有格式、注释及空对象结构。

限制：每个配置文档一次只能对应一项变更（多个配置项请放在同一项中）；同一配置不能安排多个节点。配置最多 1 MiB、单项最多 200 配置项、节点最多 20 文档。多文档顺序执行，**不是跨文档/跨应用事务**：失败即停，不自动恢复此前成功项。台账冻结执行权；网络超时或进程中断后结果须人工核对，不自动重试，也不因后续应用健康检查失败而撤销配置。

接口：`POST /api/changes/{id}/nacos-preview` 传 `environment`；编排使用 `kind=nacos` 节点及可选 `change_ids`；`POST /api/delivery/runs/{id}/nacos-restore-draft` 传 `change_id`，仅生成草稿。协议测试使用本地模拟 Nacos，未据此宣称已在你的真实服务器完成兼容验证。

### 本轮补齐顺序

各项需求分批实现，不能将保存意图或页面入口等同于执行能力。Nacos、Redis 标准连接与受限执行链路、独立 DBMS / Redis 工作台、版本制品锁定和顺序推进已接通。真实实例兼容验证仍需使用测试资源。自动代码联动、其他需求平台、并行依赖编排、跨服务恢复协调和 Splunk 仍未完成：

1. **Redis 扩展**：当前只支持单地址/标准代理和受限缓存维护命令。原生 Cluster/Sentinel、缓存值浏览/编辑和更多命令仍待实现；不实现 Redis 数据同步。
2. **DBMS、Redis 独立插件（已接通第一版）**：独立启用的操作工作台，复用全局资源、应用绑定、执行器和审核台账；不要求启用构建/部署入口。MySQL 目前为受限 SQL 查询和变更，不是完整数据库管理客户端；Redis 命令范围见下文。
3. **版本制品锁定（已接通）**：版本内每应用唯一制品；来源构建成功时展示分支与构建编号。人工确认代码覆盖后关联，首次提交锁定，同一应用多个需求只交付一个整合制品。不能据此声称系统已自动验证所选 BUG 的代码均包含在制品中。
4. **版本与代码联动**：明确基线和来源分支，创建受控集成分支，预览合并、冲突阻断、触发构建，将验证成功的产物纳入版本。创建版本本身不隐式执行数据库和配置变更。
5. **需求平台通用接入**：抽象 Bug / 需求 / 用户读取及上线回写能力，禅道为首个适配。已关闭不自动认定未上线；上线回写以成功生产执行记录为依据，独立失败重试，不影响已完成部署。
6. **高级编排**：明确节点依赖、并行边界、失败停止、可重试能力和恢复范围。应用回退与 SQL / 配置恢复分开，不承诺跨资源事务或盲目统一回滚。
7. **Splunk 只读查询**：配置只读连接、应用 / 环境 / index 映射及结果分页，验证既有 6.6.3 接口能力；不向 Splunk 写日志，不将整套平台查询语法直接假定为 SPL 等价。

## 独立数据库 / Redis 工作台

在控制台顶部 `＋` 中打开 **数据库工作台** 或 **Redis 工作台**。两者可以分别启用，不需要构建制品、部署目标或发布版本。操作仍是共享变更记录，可从部署编排选择同一项随版本执行，不复制 SQL 或命令。

配置一次：资源中心新增 MySQL / Redis 连接 → 环境设置审核人 → 应用中心创建或选择已有应用 → 工作台选择应用并“配置资源绑定”。资源身份独立于部署服务配置，删除构建/部署配置不删除资源绑定。只有管理员能接入资源应用、配置连接和绑定；成员可创建操作，审核人需为另一名已登录用户。

工作台默认打开 **查询**，**查询与提交 SQL / 命令变更**为同级高频操作，数据库另有独立的 **数据对比同步** 页面。点击提交直接进入完整编辑页，“已有变更”选择可复用记录；返回列表、切换模式或打开公共资源中心不会清空未保存的编辑草稿。查询按钮和预检按钮在编辑区上方，审批设置为页头辅助入口。查询内容可通过“以此新建变更”带入应用、资源与编辑内容；此操作不执行语句，覆盖未保存内容前需确认。

变更流程：新建或选择已有变更 → 保存草稿 → 选择目标环境与原因 → 预检 → 创建执行单（冻结快照，不执行） → 按策略审核 → 发起人或管理员显式执行。变更记录本身不绑定环境；执行单固定本次环境和资源。修改就绪项须先退回草稿；冻结版本内的变更不能退回。

**查询审批与变更审批分别配置**：管理员在工作台“审批设置”选择环境，独立保存两个开关。默认查询无需审批、变更需要审批，DBMS 与 Redis 的设置互不影响。受保护环境始终要求变更审核；关闭变更开关仍须预检、创建执行单并手动确认。关闭开关不豁免历史已冻结的审核要求；策略收紧后旧免审执行单需要重新提交。部署编排中的 SQL / Redis 节点维持原有强制审核，不受独立工作台的免审设置影响。

开启查询审批后：提交查询申请 → 另一名相关环境审核人批准 → 申请人在创建后 30 分钟内执行一次。批准、拒绝、执行使用状态版本校验；连接/凭据/任务变化、审核人被移除、过期或重复执行均拒绝。结果只返回浏览器，不存入申请记录或审计台账。服务端校验策略，不能通过直接调用查询或数据对比接口绕过。

数据库查询复用受限单表 SELECT 解析器，只支持原始显式字段及 WHERE，不支持 `*`、JOIN、函数、排序、多语句或手填 LIMIT。服务端只读事务、30 秒超时、最多 1000 行 / 2 MiB，单元格最多 64 KiB。实际读取权限仍由数据库账号决定。Redis 查询支持 GET、TYPE、TTL、PTTL、EXISTS、STRLEN、HLEN、LLEN、SCARD、ZCARD、PING，只接受资源前缀内的精确 Key。GET 使用只读 GETRANGE 限制返回大小，超过 64 KiB 标记截断，连接账号需要该只读命令权限；写命令必须进入变更提交，不支持通配符、扫描或脚本。

数据对比同步单独维护可复用任务，不绑定环境；每次选择来源和目标。任意一侧开启查询审批时提交数据对比申请，审核后结果回到任务页面。查看/编辑/勾选差异后生成 SQL 草稿，不立即写库，也不强制跳走；点击“继续预检目标库”才进入变更提交。生成草稿须核对原批准记录、任务修订、两侧连接及差异摘要，写入仍受目标环境的变更审批约束。SQL / Redis 安全限制、失败停止和不确定结果核对规则不因独立入口而放宽。当前不支持任意 SQL、完整 Redis 值编辑或自动恢复缓存。

### 插件部署与关闭

`plugins/delivery-core/manifest.yaml` 是内部共享服务：复用已有 `bin/deploy`、19803 监听和 `runtime/deploy-data`（可配置 MySQL 元数据库）。只启动一个后台进程，不在壳中展示。三个可见插件 `deploy` / `dbms` / `redis` 通过 `backend: delivery-core` 共享它，凭据、环境、绑定、审核与记录只有一份。

仅使用数据库/缓存时，在 `plugins/deploy/manifest.yaml` 添加 `enabled: false`，保留 core 及所需工作台 manifest，然后重启平台。关闭单个工作台同样添加 `enabled: false`；这不会删除数据。只要还有这些入口或资源中心在使用，不要关闭 core。core 地址、数据目录及启动参数现在配置在其 manifest，不再配置在 deploy 入口中；生产数据库环境变量名称保持原样。旧版自定义 deploy manifest 的后台参数须移动到 core，不能同时启动两份指向同一库的后台。依赖缺失会明确报错，不静默启动半个插件。

DBMS / Redis 网关只开放各自工作台能力路径，不开放构建、部署或另一个工作台的 API；公共配置走 `/api/resources/` 并执行管理员校验。独立入口仍要求平台登录来建立双人审核，不应将 19803 后台端口开放给用户。直接 `/ui/dbms` / `/ui/redis` 主要用于本机预览，正式操作使用平台壳。

## Redis 缓存维护与受审核执行

1. 资源中心新建 **Redis 缓存维护** 连接：填写 `host:port`、DB（0–15，云代理通常使用 0）、允许的精确 Key 前缀（如 `menu:`）、密码。ACL 用户名可留空；支持密码/ACL 和可信内网无认证。TLS 校验证书，不提供跳过校验选项。凭据加密保存；切换认证方式需要重填密码。
2. 云 Redis 的标准代理与自建单机使用相同 Redis 协议。平台主机需要网络连通和白名单权限；公网连接请配置 TLS。当前不是阿里云实例管理 API，不提供创建实例、规格调整或自动申请公网功能。原生 Cluster 的 MOVED/ASK 重定向及 Sentinel 不自动跟随，遇到即停止，不把命令转发到未经审核的地址。
3. 应用声明 Redis 资源别名，再按环境绑定连接；DB、前缀在连接中指定，不允许绑定覆盖。需求交付内容或独立变更都可填写命令，每行一条；保存不执行。已有只登记了 `reference` 的 Redis 记录须退回草稿重新填写结构化命令。

```text
TYPE menu:tree
TTL menu:tree
UNLINK menu:tree menu:permissions
HDEL menu:hash "field with space"
EXPIRE menu:session 600
```

白名单：`PING`、`EXISTS`、`TYPE`、`TTL/PTTL`、`STRLEN/HLEN/LLEN/SCARD/ZCARD`、`UNLINK`、`HDEL`、`EXPIRE/PEXPIRE`、`PERSIST`。TTL 设置须为正数且不超过一年。暂不支持 GET/SET 值读写、DEL、KEYS、FLUSH*、EVAL、事务、SELECT、CONFIG 等其他命令。使用 UNLINK 明确指定待清理 Key，不扫描、不展开通配符、不自动删除整个前缀。

单项变更最多 50 条命令、200 个 Key 参数、32 KiB 文本；参数最多 1024 字节。所有 Key 都必须在连接前缀内（不能是前缀本身），不允许 `* ? [ ]`。双引号内反斜线仅转义下一个字符，单引号内容为原文；不解析变量、管道或 shell。配置前缀是平台范围限制，不代替 Redis 账号 ACL；请使用最小权限专用账号。

4. 将变更标记就绪，选择目标环境做 **Redis 命令预检**。预检只认证、选择 DB 和 PING，并验证命令语法/Key 范围；不执行上述命令、不读取缓存值，也不代表已有写权限。
5. 在部署编排中添加 Redis 节点；固定模式显式选择变更，版本模式可自动汇总版本内 Redis 变更。仅有 Redis 节点时不需要版本、构建制品或部署目标。同一变更在一个执行单内只能分配一次。
6. **所有环境均强制审核**：环境管理里配置审核人员，不必把开发/测试整体改为受保护环境。发起人不可自审；真实使用须启用平台登录并配置另一名成员，匿名本地模式不作为双人审核保障。执行前再次验证审核人资格、变更状态/内容和连接目标/DB/前缀/用户身份；凭据可以轮换，目标变化须重新提交审核。
7. 执行单冻结目标与命令，Key 的实时内容不冻结、不做值 CAS。每条命令都有持久台账（reserved / executing / success / uncertain），节点按顺序显式执行，失败停止后续命令。整数结果表示数量或状态，不代表业务验证。超时、进程中断和响应丢失 **不自动重试**，因为命令可能已经生效；先核对台账和实际缓存，再另建变更审核。不同环境解析到同一 Redis 地址+DB 时，同一变更不重复执行。

Redis 节点不保证跨命令、跨应用事务，也不自动恢复已删除缓存。缓存应能由业务重建；不要将无法恢复的数据当缓存清理。命令和 Key 会进入审核快照，不用于敏感值或密钥。连接错误、ACL 拒绝、Key 类型错误、原生 Cluster 重定向显示分类提示，不回显上游错误原文或密码。

API：`POST /api/changes/{id}/redis-preview` 传 `environment`；编排节点 `kind=redis`，可指定 `change_ids`；`GET /api/redis-executions?run_id=...` 查看逐命令台账。没有直接写命令接口。独立工作台 API 使用 `/api/workbench/{dbms|redis}/` 前缀，`GET/PUT policy?environment=...` 配置审批，`POST query` 执行免审只读查询，`GET/POST query-requests` 管理查询申请，`POST query-requests/{id}/{approve|reject|execute}` 审核和执行。

测试：真实 Go Redis 客户端连接本地一次性 RESP 测试服务，覆盖认证、DB 选择、审核、精确命令参数、并发防重、响应丢失、目标漂移、版本范围、需求内容保存和只读预检；Chrome 使用接口拦截测试，不访问真实 Redis。尚未宣称在你的云 Redis 或自建实例完成兼容验收。

## Git 分支同步与筛选

默认分支、单次构建、一键部署、独立代码变更和需求交付内容使用同一分支选择组件。打开下拉首次读取远程分支，也可点击 **同步分支** 刷新；输入关键词筛选，手填分支名按回车确认。同步不会替换当前选择，不拉取源码、不创建分支、不触发构建。构建弹窗覆盖仅作用于本次运行，留空沿用应用默认分支；应用默认也为空时，构建使用远程默认分支。同步或构建提交失败时保留输入。

新应用在填写仓库时即可选择资源中心的 Git 凭据；编辑构建配置同步时使用当前未保存的仓库与凭据选择。HTTPS/PAT 与 SSH 私钥不能混用，服务主机、协议、端口必须匹配；SSH 始终校验已确认指纹，不自动信任未知主机。凭据只用于子进程环境和权限受限临时文件，结束后清理，不包含在命令行、接口响应或上游错误正文中。

一个代码内容关联多个应用时，同步每个应用的仓库和所选凭据，仅展示共同分支；没有共同分支时应拆分内容或核对手填分支。任一仓库读取失败不当作完整同步成功，切换应用/仓库/凭据后旧响应失效，已有输入不丢失。

同步 API 为只读探测 `POST /api/git/branches`：已保存应用传 `{"service":"app"}`；接入或编辑草稿可传 `git_url`、`connection` 覆盖，显式空连接表示不使用平台凭据。返回 `branches: [{name,commit}]`、`default_branch` 和 `synced_at`。只支持 HTTP(S)/SSH 网络仓库，拒绝本地路径、带内嵌 Token 的地址及外部 Git helper 协议；20 秒超时、最多 10000 分支、并发上限 6。

**执行位置是部署插件所在平台主机，不是远程 Runner**，主机需安装 Git，并能访问仓库。未选凭据时 HTTPS 不读取用户 credential helper，SSH 只使用平台用户已有私钥/known_hosts；平台不自动复制 Runner 的密钥。前端多应用一次最多 20 个、并发探测 3 个，不持久缓存远程分支，实际构建仍会重新访问仓库。

## 可复用 MySQL 数据同步任务

主入口：数据库工作台 → **数据对比同步**，不再与需求、变更、版本平级。需求的“编辑交付内容 → 引用同步任务”会打开数据库工作台并携带需求关联，原部署工作区及草稿保活；也可解除本次关联，单独生成同步变更。未启用 DBMS 时保留就地入口，避免破坏已有部署流程。任务定义不绑定环境，执行时选择来源与目标，生成的差异 SQL 冻结任务修订和目标环境。

在数据库工作台生成关联同步草稿后，壳向原部署工作区发送变更通知。交付编辑器只合并新增记录并更新摘要，不覆盖未保存输入；已有记录同时被他人修改时保留输入并提示核对。关闭时保留的交付草稿在重新打开后也会核对新增内容，独立页面返回浏览器焦点时重新核对。冻结同步 SQL 不因保存普通草稿而被改写。此保活不等同于浏览器刷新后持久恢复。

## 紧凑交互、批量变更与说明图片

变更列表与发布版本均使用表格，正文不铺在列表。变更可按标题/引用、类型、应用、创建人、状态、关联关系筛选；版本可按版本号/标题/说明、应用、创建人、状态筛选。“只看我的”按平台创建人筛选，与外部 Bug 的指派人筛选不同。列表使用服务端分页（20/50/100 条），不会只在最近 500 条里查找；进入详情再返回，以及切换变更/版本页签，会保留各自筛选、页码和表格滚动位置，刷新浏览器后不承诺保留。

变更支持选择**本页**多条记录，一次纳入可编辑的草稿版本；版本选择支持搜索和加载更多。提交前读取最新草稿范围，保留已有需求和独立变更，并去重追加本次选择；版本已经冻结则拒绝修改。翻页、修改筛选或刷新列表会清空本页选择，避免误选隐藏记录。此操作只改规划范围，不触发构建、数据库执行、配置发布或部署。

发布版本表格展示版本号、名称、工作项/变更/关联应用数量、创建人、更新时间与版本状态。应用数包括代码和配置等变更关联的全部应用，并非实际部署服务数；`ready` 显示“已冻结”。查看详情、编辑范围和发起交付入口仍保留，各环境的执行结果在版本详情的交付记录中查看，不把某个环境执行成功当作整个版本的状态。

变更管控把标题、页签和操作合在一行；无关的应用/环境上下文不占全局目录页空间，应用详情及日志、监控仍保留所需上下文。通用侧边栏默认折叠，悬停或键盘聚焦展开且不挤压正在编辑的内容。人员筛选、只看我的、分页仍保留为工作项列表的一级操作；说明在详情显示，不铺满列表。

变更列表的“新建变更”支持在一个编辑器内连续添加代码、多应用、SQL、Nacos、Redis 与人工操作，可选共同关联需求/Bug。“保存全部变更”使用一个数据库事务生成多条独立草稿；某一项无效时全部回滚，不触发构建、执行或发布。关闭后本工作区保留未保存的批量草稿，刷新/退出浏览器不保证恢复。API：`POST /api/changes/batch`，字段 `changes` 与可选的 `also_work_item_ids`；不接受现有记录 ID 或冒充冻结的数据同步计划。

自定义需求/Bug 的说明支持 Markdown 编辑与预览、选择多图、粘贴及拖入图片。已有来源 HTML 不被强制转换，按安全富文本展示。图片预览支持逐张查看；外部图片仍仅点击后加载。平台图片上传接口为 `POST /api/work-item-attachments`（multipart 字段 `file`），读取为 `GET /api/work-item-attachments/{id}`，正文以 `attachment:随机ID` 引用。单张最多 8 MiB，仅 PNG/JPEG/GIF，最多 4000 万像素，每个工作项最多 30 张；SVG、HTML、脚本不接受。未关联图片仅上传者/管理员可读；保存时验证所有权并在同一事务关联需求，不能盗用其他草稿的附件。Markdown 与 HTML 都经过清洗，不执行脚本或事件。

附件文件位于部署核心持久数据目录的 `work-item-attachments/`，元数据和说明格式在部署数据库中（SQLite/MySQL 的增量迁移）。备份/迁移必须同时保留部署数据库、凭据密钥及此附件目录，不能只复制程序包。取消上传后的未关联附件暂保留，每人最多 200 张，不自动清理历史需求图片。

1. 新建任务，选择应用、逻辑数据库资源，填写来源/目标查询 SQL 和匹配键。任务不保存来源或目标环境，也不要求先绑定环境数据库；只校验应用声明了该 MySQL 资源。任务保存后可反复使用。
2. 查询当前仅支持单表显式字段 `SELECT id,name FROM menu WHERE id > 0`，两个查询返回相同字段与顺序。禁止 `*`、别名、JOIN、函数、子查询、聚合、ORDER BY、LIMIT、变量与多语句；读取使用只读事务，最多 1000 行 / 2 MiB，UTF-8 文本单元格最多 64 KiB。匹配键必须完整对应目标主键或唯一索引，且结果无重复/NULL 键。
3. 在“本次对比”选择来源和目标环境，点击“对比数据（只读）”。两侧的实际数据库通过该应用的逻辑资源别名及环境绑定解析；环境不能相同，也不能绑定同一数据库。展示新增/更新差异、原值与来源值；目标独有行保留，不生成删除。支持修改待同步值（包括 NULL），匹配键不可修改。改变任一环境或任务定义后清空旧对比与勾选，必须重新对比，不修改任务修订。
4. 勾选 1–50 行并“生成同步草稿”。服务器重新对比，任务/资源身份或来源/目标数据有变化则拒绝旧结果。草稿记录任务编号、修订、所选差异、目标环境和目标基线；从需求打开时自动关联该需求，不执行数据库写入。
5. 在变更列表或需求详情核对并标记就绪，纳入版本；部署编排添加 **SQL 节点**（可命名“菜单同步”）执行该草稿，再串服务发布和人工确认。上线依赖的是本次冻结同步计划，不能直接执行会不断变化的任务定义。
6. 生产等受保护环境必须审批，不能自审。预览/提交时再次校验目标数据与连接身份；执行时校验结构、绑定、内容摘要并锁定选中行，在一个 InnoDB 事务内更新，失败回滚，台账阻止重复执行。普通 SQL 的单表 DML 限制保留，仅同一同步快照的互不重叠唯一键操作允许批量执行。

同一任务可用于“开发 → 测试”及“测试 → 生产”，每次都重新选择两侧环境、重新对比并生成目标环境的草稿；已经生成的同步 SQL 不允许直接修改，不自动跟随任务后续修订变化。旧任务文档中的来源环境不再作为任务属性返回或使用，重新保存后去除；旧的已冻结同步快照仍保留原环境约束。当前只实现新增和更新，不做自动删除、跨表关联、外键顺序推断或通用 Redis 同步；含反斜线转义等不被现有安全 SQL 方言支持的数据会在生成阶段报错，不会执行。SQL 草稿/差异快照包含实际业务值，不用于同步密钥，注意平台数据访问和备份权限。

API：`GET/POST /api/data-sync/tasks`、`PUT /api/data-sync/tasks/{id}`（带 `revision`），任务定义没有环境字段。`POST /api/data-sync/tasks/{id}/compare` 必须传 `source_environment`、`target_environment`；`POST /api/data-sync/tasks/{id}/freeze` 传同一对环境、对比 `digest`、`rows:[{key,after}]`，可选 `work_item_id/work_digest`。对比摘要同时绑定来源/目标环境、数据库身份、任务修订及两侧数据；只传旧 `environment` 字段会拒绝，不隐式选用历史来源。任务元数据存于 `data_sync_tasks`，支持 SQLite/MySQL，无需改变表结构；执行仍使用既有 `sql_execution_ledger`。

## 构建环境

入口：**接入/编辑应用 → 构建方式 → 构建环境**，也可在 **应用 → 构建** 或 **交付设置** 修改。

- **本机工具**：兼容旧应用，沿用 Runner 已安装的工具和 PATH/JAVA_HOME，不自动修改系统工具。
- **隔离容器**：按次启动临时构建容器，完成或超时后清理。可选 JDK 8/17/21 + Maven 3.9.9 或 Gradle 8.14.3，Node.js 20/22 + npm。
- **自定义镜像**：适合 Java + Node 组合、特殊编译工具、固定版本或内网镜像，例如已有的 `estate-gis-builder:java21-node22`。必须指定标签或 digest，镜像应包含 bash，并允许以 Runner 的 UID/GID 运行；不支持通过表单填写额外 Docker 参数或任意宿主机目录挂载。

`auto` 优先使用仓库里的 `mvnw` / `gradlew`，没有 Wrapper 时才使用所选环境内的 mvn / gradle。Wrapper 的版本不会被环境模板覆盖。平台对常见的 Gradle Wrapper/JDK 不兼容组合提前报错；完整兼容矩阵以 [Gradle 官方说明](https://docs.gradle.org/current/userguide/compatibility.html) 为准。

运行要求：

1. Docker 必须安装在**执行部署插件的 Runner 主机**上，平台运行账号能够访问 Docker 引擎。当前仍是本地 Runner，不是远程执行集群。
2. 首次构建可能下载镜像和 Wrapper/项目依赖；内网可先 `docker load` 导入镜像，使用自定义内网镜像并配置依赖仓库。不会自动修改宿主机 DNS 或使用 host 网络。
3. 镜像标签先解析为本地 image ID，再按该 ID 执行，实际 ID 和工具版本进入构建日志。已有本地镜像不自动更新；需要升级时由管理员更新镜像或更改配置。
4. 仅编译步骤进入容器；源码拉取和制品归档仍在宿主机。Docker 镜像构建继续使用本机 Docker，不挂载 Docker socket 到编译容器。
5. 挂载当前工作区、步骤脚本（只读）、输出目录和按应用/镜像隔离的缓存；Maven settings.xml 按配置只读挂载。HOME 为 `/lp-home`，Gradle 用户目录为 `/lp-home/.gradle`。不挂载整份宿主机 HOME、SSH 密钥或 Jpom secrets。
6. 构建变量组显式注入，敏感值不放 Docker 命令行；不要用变量组覆盖 HOME/PATH/JAVA_HOME/GRADLE_USER_HOME。Gradle 私服凭据仍通过 `GRADLE_REPOSITORY_URL/USERNAME/PASSWORD` 供项目读取。

此模式用于工具依赖隔离，**不是运行恶意代码的安全沙箱**。Docker 引擎访问权限接近主机管理员权限；不要开放给不可信用户，也没有自动资源配额或缓存淘汰功能。

## 一键部署

完成代码、构建和环境配置后，在应用标题区点击 **一键部署**，选择目标环境即可把一次操作串成：拉取代码 → 构建 → 登记不可变制品 → 创建发布单 → 自动发布。构建失败不会触发发布；普通环境会直接执行，受保护环境只创建待审批发布单，不会绕过审批。流水线详情会显示本次目标环境，并在构建完成后补充自动创建的发布单编号。

“开始构建”仍只生成制品，适合验证代码或后续手工选择发布版本；“一键部署”适合日常把当前分支直接交付到一个已经配置好的环境。开始前平台会检查主机组、审批人、发布原因和是否已有进行中的发布单，避免构建成功后才发现目标不可用。

## 标准 Java 发布

入口：**应用 → 环境 → 配置部署环境 → 标准 Java**。新建 Java 环境默认标准模式；旧环境继续使用原自定义命令，不自动切换。

1. 选择环境和该环境的主机组，填写独立部署目录（例如 `/home/work/zfb/ai/devops-service`）。
2. 选择运行 JDK 21，填写主机上的 JDK 目录 `/home/work/runtime/jdk-21`；留空使用主机 PATH 中的 java。不会自动安装 JDK。
3. JVM 参数每行一个，不加 shell 引号，例如：

   ```text
   -Xms256m
   -Xmx1024m
   -XX:+UseG1GC
   -Dfile.encoding=UTF-8
   -Duser.timezone=Asia/Shanghai
   ```

4. 应用参数每行一个，例如 `--server.port=8889`；**就绪检查端口**填 `8889`。端口字段仅用于检查，不改变程序监听配置。也可以填写应用真实存在的完整 HTTP 健康检查 URL，例如 `http://127.0.0.1:8889/actuator/health`；不要只填路径或盲填不存在的 actuator 地址。
5. 环境变量按环境配置并加密保存。例如开发环境设置 `SPRING_PROFILES_ACTIVE=dev`，测试设置 `SPRING_PROFILES_ACTIVE=test`；Nacos 注册 IP、网卡名及服务依赖地址分别按目标环境设置。模型 API Key 等敏感值只放环境变量，不写 JVM 参数或脚本。
6. **健康检查失败时**默认停止新版本并恢复旧版本。非保护环境也可选择“停止新版本、不恢复旧版本”或“保留新版本运行”以便排障；这两种情况发布仍标记失败并停止后续批次。受保护环境固定自动回滚。

发布过程：校验制品及应用 class 的 JDK 要求 → 上传新版本 → 检查主机 JDK → 优雅停止旧版本 → 切换 current → 启动 → 进程 + 端口/HTTP 就绪检查。嵌套依赖包的 JDK 要求仍需构建测试与启动检查确认。

每个版本拥有独立的 `app.jar`、`service.sh` 和权限受限的 `runtime.env`；回滚恢复旧制品及旧变量。进程 PID 必须对应当前版本的精确 JAR 路径，不能只凭 PID 或宽泛 pkill 杀进程。停机超时不会自动强杀；没有旧版本时首次发布失败不会显示为“已回滚”。

发布完成后可进入 **应用 → 环境 → 实例管理**，实时读取每台主机的进程、PID 和实际版本，并执行启动、停止、重启与就绪检查。实例操作与发布共用目录锁，发布进行中不能并发启停；受保护环境需要二次确认和操作原因，成功或失败都会写入审计日志。

目录示例：

```text
devops-service/
  current -> releases/deploy-123
  releases/deploy-123/{app.jar,service.sh,runtime.env}
  logs/application.log
  .devopsplatform.pid
  .devopsplatform-owner
```

注意：

- 标准模式只支持 Linux，使用 bash、coreutils；HTTP 检查需要 curl，检查地址从部署主机访问。端口检查使用 127.0.0.1，应用需监听该地址或通配地址。
- 不会自动停止/接管 Jpom 的进程。首次迁移先确认新配置，在发布窗口停止旧服务或选择独立端口，避免双平台争用。旧 Jpom 配置暂时保留作为人工回退方案。
- 单机替换存在短暂停机；这不是零停机部署。主机组可沿用平台分批发布机制。
- 当前标准模式使用受控的后台 Java 进程，不提供开机自启、崩溃自动重启；需要进程守护的场景继续使用自定义 systemd 命令。
- 历史版本和应用日志暂不自动清理，需要运维设置保留策略。`runtime.env` 是主机上权限受限的明文快照，应限制 SSH 用户和备份访问。
- 发布锁记录操作所有者和开始时间。升级前遗留的空锁会在下一次操作时自动恢复；带所有者的活动锁不会被其他发布删除，超过 30 分钟才会作为陈旧锁回收。日志会明确打印锁所有者和年龄，仍可据此排查异常中断。
